# Google Classroom × Colab で行う Python 授業ガイド（教員用）

**「基本事項 → 例題 → 課題 → 提出」** の流れで、段階的に Python を学ぶ授業用の教材一式です。
各回の教材は Colab ノートブック（`.ipynb`）になっており、Google Classroom で生徒ごとにコピーを配布し、生徒がプログラムを書いて提出します。

## 1. ファイル構成

```
classroom/
├── README.md        … このガイド（教員用）
└── lessons/         … 生徒に配布する教材（各回1ファイル）
    ├── lesson01_出力と計算.ipynb
    ├── …
    └── lesson10_総合課題_ミニプロジェクト.ipynb
```

> 🔒 **教員用の解答例は、生徒に見られないようにこのリポジトリには置いていません。** 先生の Google ドライブの、生徒と共有していないフォルダで管理してください。

各回の教材（`lessons/`）は、どれも同じ構成です。

| セクション | 内容 |
| --- | --- |
| 今日の目標・授業の流れ | その回で身につけること |
| 名前欄 | 生徒が学年・組・番号・名前を書く |
| **1. 基本事項** | 文法の説明と、実行して確かめるサンプルコード |
| **2. 例題** | 例題・プログラム・解説 |
| **3. 課題** | 課題1・2（基本）、課題3（応用）。それぞれに実行例と解答用セル |
| 4. ふりかえり | わかったこと・つまずいたこと・自己評価 |
| 5. 提出方法 | 全セル実行 → 保存 → Classroom で提出 |

> 📘 Colab を初めて使うクラスでは、第1回の前にリポジトリ直下の [Colab の使い方の手引き](../colab-python-guide.md) と [練習用ノートブック](../notebooks/python_practice_01.ipynb) を使って、操作に慣れる時間（第0回）をとるのがおすすめです。

## 3. 1コマの授業の流れ（50分）

| 時間 | 活動 | 教員の動き | 生徒の動き |
| --- | --- | --- | --- |
| 0〜5分 | 導入 | 今日の目標を示す。前回の振り返り | Classroom から課題を開き、名前欄を書く |
| 5〜20分 | **基本事項** | 説明しながら、サンプルを一緒に実行する | サンプルを実行し、値を変えて試す |
| 20〜30分 | **例題** | 例題を実行し、考え方を解説する | 実行し、解説を読む。少し変えて試す |
| 30〜45分 | **課題** | 机間指導。つまずいている生徒を支援 | 課題1・2 → 余裕があれば課題3 |
| 45〜50分 | **ふりかえり・提出** | 提出方法を確認させる | ふりかえりを書いて「提出」 |

> 💡 授業中に終わらなかった場合は、期限を「次の授業の前日」などに設定し、家庭学習で仕上げられるようにします。

## 4. 事前準備

### 4-1. Colab が使えるか確認する（最初に1回だけ）
学校の Google Workspace for Education アカウントでは、**管理者が Colab を無効にしている** ことがあります。
事前に教員アカウントと生徒用のテストアカウントで <https://colab.research.google.com/> を開き、ノートブックを作れるか確認してください。
使えない場合は、学校の Google Workspace 管理者に「Colaboratory」の利用を有効にするよう依頼します。

### 4-2. 教材を Google ドライブに置く
1. GitHub の `classroom/lessons/` から、使う回の `.ipynb` ファイルをダウンロードする
   （ファイルを開いて右上の「Download raw file」ボタン）
2. Google ドライブに `Python授業/配布用` のようなフォルダを作り、アップロードする
3. 解答例は **生徒と共有しない別のフォルダ** に置く

> ✏️ ドライブ上でダブルクリック →「アプリで開く」→「Google Colaboratory」で開けば、問題文や課題を学校の実態に合わせて書き換えられます。

### 4-3. Classroom にトピックを作る
クラスの「授業」タブ →「作成」→「トピック」で、`Python プログラミング` などのトピックを作っておくと、課題が整理されて生徒も探しやすくなります。

## 5. Classroom で課題を出す手順

1. クラスの **「授業」** タブ → **「＋作成」** → **「課題」**
2. **タイトル**：例）`第1回 出力と計算`
3. **課題の詳細**：下の「課題の説明文テンプレート」を貼り付ける
4. **追加**：「Google ドライブ」をクリックし、配布用フォルダから該当回の `.ipynb` を選ぶ
5. 添付したファイルの右側のメニューで **「各生徒にコピーを作成」** を選ぶ ← ⚠️ **ここが最重要**
   - 「生徒はファイルを閲覧可能」のままだと、生徒は書き込めません
   - 「生徒はファイルを編集可能」にすると、全員が同じファイルを書き換えてしまいます
6. 右側で **点数**（例：10点）、**期限**、**トピック** を設定する
7. （任意）**ルーブリック** を作成する（[8. 評価基準](#8-評価基準ルーブリック例) を参照）
8. **「課題を作成」**（または「予定を設定」で授業の開始時刻に公開）

### 課題の説明文テンプレート

```
【第○回 ○○○○】
今日の目標：○○○○

＜進め方＞
1. 添付のファイルを開く（開けない場合は、上部の「アプリで開く」→「Google Colaboratory」）
2. 名前欄に学年・組・番号・名前を書く
3. 「基本事項」「例題」を読み、コードを実行して確かめる
4. 「課題」のセルにプログラムを書いて実行する（課題1・2は必須、課題3は挑戦）
5. 「ふりかえり」を書く
6. 「ランタイム」→「すべてのセルを実行」で動作を確認し、Ctrl+S で保存する
7. この画面に戻って「提出」を押す

＜期限＞ ○月○日（○）○時まで
```

## 6. 生徒の操作手順（生徒への説明用）

最初の授業で、次の流れを画面を見せながら説明します。

1. Classroom で課題を開き、添付されている **「（自分の名前）- lesson01_….ipynb」** をクリック
2. プレビュー画面が出たら、上部の **「アプリで開く」→「Google Colaboratory」** を選ぶ
   - 2回目以降は、自動的に Colab で開くことが多いです
3. 名前欄をダブルクリックして名前を書く
4. 説明を読みながら、コードセルを **Shift + Enter** で実行していく
5. 課題のセルの `# ここにプログラムを書く` の下にプログラムを書き、実行する
6. **「ランタイム」→「すべてのセルを実行」** でエラーがないか確かめる
7. **Ctrl + S** で保存する
8. Classroom のタブに戻り、**「提出」** を押す

> ⚠️ **実行結果が表示された状態で保存・提出する** よう指導してください。実行していないと、教員側で結果が見えません。
> 提出後に直したいときは「提出を取り消し」→ 修正 → もう一度「提出」。

## 7. 採点・返却の手順

1. 課題を開き、**「生徒の提出物」** タブを開く
2. 生徒の名前をクリック → 添付ファイルを **Colab で開く**
3. 確認するポイント
   - 課題セルの下に **実行結果が出ているか**、実行例と同じ（または正しい）結果か
   - 必要なら、教員がセルを実行し直して動作を確かめる（「ランタイム」→「すべてのセルを実行」）
   - ふりかえりの記述
4. 採点画面で点数を入力し、**限定公開コメント** でフィードバックを書く
   - 例：「課題3の考え方はよいです。`range(1, n)` だと n が含まれないので、`range(1, n + 1)` にしてみよう」
5. **「返却」** を押す

> 💡 解答例は一例です。生徒が別の書き方をしていても、正しく動けば正解として扱いましょう。
> 「さまざまな書き方があること」を授業の最後に紹介すると、学びが深まります。

## 8. 評価基準（ルーブリック例）

各回 10 点満点の例です。Classroom のルーブリック機能に登録すると、採点が速くなります。

| 観点 | 3点 | 2点 | 1点 | 0点 |
| --- | --- | --- | --- | --- |
| **課題1・2（基本）** | 両方とも正しく動く | 片方が正しく動く | 書いてあるが動かない | 未着手 |
| **課題3（応用）** | 正しく動く | 一部が正しく動く | 取り組んだ形跡がある | 未着手 |
| **プログラムの書き方** | 変数名がわかりやすく、コメントで説明がある | 変数名かコメントのどちらかに工夫がある | 動くが読みにくい | — |
| **ふりかえり**（1点） | 具体的に書けている（1点） | — | — | 未記入（0点） |

第10回（総合課題）は次の観点で評価するとよいでしょう。

| 観点 | 内容 |
| --- | --- |
| 動作 | 正しく動き、想定外の入力でも止まりにくい |
| 活用 | 学んだ内容（入力・条件分岐・繰り返し・リスト・関数・ライブラリ）を 3 つ以上使っている |
| 読みやすさ | 変数名・関数名・コメントがわかりやすい |
| 工夫 | 独自の機能や表示の工夫がある |
| 説明 | テキストセルで「何を作ったか」「工夫した点」を説明できている |

## 9. よくあるトラブルと対処

| 症状 | 対処 |
| --- | --- |
| 生徒がファイルを編集できない | 課題の添付が「各生徒にコピーを作成」になっていない。課題を **公開する前** に設定する（公開後は変更できないため、課題を作り直す） |
| 「アプリで開く」に Colab が出ない | 「アプリで開く」→「アプリを追加」で “Colaboratory” を検索して追加する。それでも出ない場合は、管理者が Colab を無効にしていないか確認 |
| 提出物に実行結果が表示されていない | 生徒が実行せずに保存している。「すべてのセルを実行 → 保存 → 提出」を徹底させる |
| `input()` のセルで先に進めない | 入力待ちのまま。セルの下の入力欄に値を入れて Enter。止めたいときは ■ ボタン |
| 無限ループで止まらない | セル左の ■ ボタン、または「ランタイム」→「実行を中断」 |
| `NameError` が出る | 上のセルを実行していない。「ランタイム」→「前のセルを実行」 |
| 生徒が解答例を見てしまう | 解答例はドライブの別フォルダで管理し、生徒と共有しない。公開している GitHub リポジトリなどには置かない |

## 教材を改訂するとき

各ノートブックは Colab で開いて直接編集できます。数値や題材（地域の話題・学校行事など）を生徒になじみのあるものに変えると、意欲が高まります。
